# รายงาน CER — วัดคุณภาพ Tesseract 5 โดยตรง

ตัวเลขในรายงานนี้ตอบคำถามที่ `ocr_eval_report.md` ตอบไม่ได้: **Tesseract อ่านผิดแค่ไหน**

## วิธีวัด (paired-page protocol)

ground truth ระดับข้อความที่คนพิมพ์เองไม่มีในโปรเจกต์นี้ จึงใช้หน้าที่ PDF ฝังข้อความมาแล้ว (`text_layer`) เป็น reference แล้วส่งภาพของ *หน้าเดียวกัน* เข้า Tesseract เพื่อเทียบกัน

1. สุ่มหน้า `extraction_method = 'text_layer'` ที่มีข้อความยาวพอ — ต่อเล่มไม่เกิน 4 หน้า (seed คงที่ รันซ้ำได้ผลเดิม)

2. render หน้าเป็นภาพที่ **300 DPI** — ค่าเดียวกับ `run_ocr.py`

3. เรียก Tesseract ด้วย `-l tha+eng --psm 6` — argument ชุดเดียวกับ pipeline จริง

4. เทียบผลกับ reference → CER / WER / ความแม่นของรหัสวิชา 8 หลัก


**ขนาดชุดวัด:** 14 เล่ม / 56 หน้า / 103,870 อักขระอ้างอิง

## อ่านผลอย่างไร

เกณฑ์ที่ตั้งไว้ในสเปกคือ CER ≤ 0.05 ผลที่วัดได้อยู่ระหว่าง **0.038** ถึง **0.205** ขึ้นกับว่านับความผิดของ ลำดับการอ่านเข้าไปด้วยหรือไม่


ตัวเลขสามค่านี้ต้องอ่านด้วยกัน ไม่ใช่เลือกค่าใดค่าเดียว (ทั้งสามใช้ตัวหารเดียวกัน):

- **CER ไม่นับช่องว่าง = 0.205** — ผลกระทบรวมที่ downstream เจอถ้าอ่านทั้งหน้าเรียงตามลำดับ
- **line-match CER = 0.045** — คุณภาพการรู้จำอักขระของ Tesseract หลังตัดปัญหาลำดับออก
- **bag CER = 0.038** — ขอบล่าง (การอ่านผิดหักกลบกันเองได้)


### ข้อสรุปหลัก

**error ส่วนใหญ่ไม่ได้มาจาก Tesseract อ่านตัวอักษรผิด แต่มาจากลำดับการอ่าน** — ส่วนต่างระหว่าง CER ไม่นับช่องว่าง กับ line-match CER เท่ากับ 0.160 ซึ่งมากกว่าตัว line-match CER (0.045) เอง


สาเหตุ: มคอ.2 มีหน้าตารางเยอะ (ตารางเปรียบเทียบหลักสูตรฉบับปรับปรุง, ตาราง PLO mapping, ประวัติอาจารย์) `--psm 6` มองหน้าเป็นบล็อกข้อความเดียว Tesseract จึงไล่อ่านทีละคอลัมน์ ขณะที่ text layer ไล่ทีละแถว ข้อความเดียวกันแต่เรียงต่างกันจึงถูกนับเป็น error เต็ม ๆ


**ผลต่อการตัดสินใจเรื่อง OCR engine:** การรู้จำอักขระของ Tesseract อยู่ที่ 0.045 (อยู่ในเกณฑ์ 0.05) การเปลี่ยนไป Typhoon OCR จะช่วยได้มากหรือน้อยขึ้นกับว่ามันจัดการ layout ตารางได้ดีกว่าหรือไม่ (Typhoon เป็น VLM คืนผลเป็น markdown จึงมีโอกาสรักษาโครงตาราง ได้ดีกว่า) แต่ถ้าจะแก้ให้ตรงจุดที่สุด สิ่งที่ควรทำก่อนคือ **layout analysis** — ตรวจหาคอลัมน์/เซลล์แล้วส่ง OCR ทีละบล็อก ซึ่งใช้ Tesseract เดิมได้เลย


### สิ่งที่ยืนยันได้จากตัวเลขอื่น

- รหัสวิชา 8 หลักอ่านตรง **0.935** (86/92) และสร้างเกินมา 0 รหัส — ค่านี้ทนต่อการสลับลำดับ และเป็นตัวที่ผูกกับ downstream ที่สุด เพราะ pipeline ใช้รหัสวิชาเป็นกุญแจสร้างตาราง `course`

- `ref out-of-charset` สูงในเล่มไหน แปลว่า text layer ของเล่มนั้นเองก็เพี้ยน ค่า CER ของเล่มนั้นจึงสูงเกินจริง (โทษ OCR ไม่ได้เต็มร้อย)


### ข้อจำกัดที่ต้องพูดตอนนำเสนอ

- reference คือ text layer ไม่ใช่คนพิมพ์ ตัวเลขชุดนี้จึงเป็น **proxy** ของ CER จริง ไม่ใช่ CER ต่อ ground truth มนุษย์

- ชุดวัดมี 56 หน้าจาก 14 เล่ม (สุ่มด้วย seed คงที่) ไม่ใช่ทั้ง 3,689 หน้า

- เทียบกับ `ocr_eval_report.md`: ที่นั่น field accuracy วัดจากหน้า text layer ทั้งหมด (จากหน้า OCR = 0) จึงไม่สะท้อนคุณภาพ OCR — สองรายงานวัดคนละอย่าง ต้องอ่านคู่กัน
